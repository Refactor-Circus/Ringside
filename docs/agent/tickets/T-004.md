## Problem

When a gate command is refused or runs in the wrong checkout, the gate reports it as a blocker finding, the loop counts a red round and sends empty rework (Atrium: 3 red rounds, 3 empty commits).

## Desired outcome

- The GATE schema gets a `not_run` channel.
- Gate commands are rewritten cwd-proof (`composer --working-dir=<tree> [exec] ...`) by a helper.
- Spec done-definition commands run every round.
- A non-empty `not_run` escalates at once (stage gate, no red round, no rework, no commit).
- `factory.md` documents the fix; workflow simulations cover it.

## Out of scope

- Config verify default.
- Runner allowlist changes.
- Merging.
