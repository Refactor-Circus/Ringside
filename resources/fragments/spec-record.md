**The spec's record.** A spec folder lives in its job's worktree, on the job branch (`ring-master/<id>`), never in this checkout: `vendor/bin/ringside spec path <id>` prints where (a spec already merged is on `{{base_branch}}`). Read and write the spec's files there, by that absolute path. The folder is committed with the job, so put scratch files (a PR or issue body, a comment draft) in your scratchpad, never in it. When this stage has written what it writes, commit it: `vendor/bin/ringside spec commit <id> "<what the stage did, e.g. shaped>"`. It commits the spec folder alone, so the job branch keeps every change and decision. Never commit, stash or switch branches in this checkout.
